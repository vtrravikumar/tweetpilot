# Vichar 1.1.0 — Release and Operations Notes

**Date:** 2026-10-11  
**Chrome Web Store status:** Submitted; pending review at time of writing  
**Extension version:** `1.1.0`

## Release contents

- Razorpay prepaid credit packs:
  - ₹19 for 1,000 generations
  - ₹49 for 5,000 generations
  - ₹99 for 15,000 generations
- Hosted Razorpay Payment Links, server-side payment verification, signed `payment_link.paid` webhook validation, and idempotent credit fulfilment.
- Free trial allowance set to 10 generations.
- Purchase UI explains one-time purchases and that there is no subscription.
- Extension manifest, package metadata and lockfile version set to `1.1.0`.
- Temporary internal test-license endpoint removed from the production Worker code; `VICHAR_TEST_LICENSE_SECRET` removed from the Worker.
- Owner license reactivated and verified in the extension UI as **Owner access · Unlimited generations**.

## Current limits and operational notes

- Free extension license: 10 total generations per free grant.
- Production burst setting: 30 requests/minute.
- These are separate controls: the burst setting is not a credit allowance.
- Rate limiting is not yet license-aware. Paid and owner licenses can still be subject to the configured shared burst protection. Do not describe paid use as unlimited-speed.
- Keep `backend/wrangler.jsonc` aligned with the intended Cloudflare Production variables to prevent a future Wrangler deployment from restoring a stale value.
- Production secrets remain in Cloudflare; never commit or document secret values.
- The website at `vtrrk.in/vichar/` remains a separate free product surface and must not consume extension credits.
- No website repository changes were made as part of this release.

## Follow-up

1. Monitor Chrome Web Store review and verify public installation after approval.
2. Implement license-aware rate limiting: preserve free-tier abuse controls while letting paid users consume purchased credits at their chosen pace, with a generous emergency safeguard against runaway traffic.
3. Keep the free allowance and burst rate documented independently.
4. Re-test checkout and webhook fulfilment safely if payment code or Worker configuration changes; do not complete a live charge just for a smoke test.
